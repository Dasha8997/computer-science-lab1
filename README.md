## 1. Описание системы

Название: Canva

Ссылка: https://www.canva.com/

Назначение: — это графический редактор для дизайна и создания визуального контента: изображений, видео, анимации.

Целевая аудитория: 
- блогеры, частные пользователи
- малый бизнес(у которого нет желания нанимать дизайнера)
- студенты, преподаватели, школьники и другие люди взаимодействующие с образовательными учреждениями
- корпоративные команды
- волонтёры
- маркетологи и специалисты по продвижению

Основные возможности: 
- работа с шаблонами-макетами (для создания различных печатных и цифровых дизайнерских продуктов)
- создание дизайнерской продукции с использованием готовых элементов дизайна (например подобранных шрифтовых пар, элементов графики)
- редактирование фото, видео (есть возможность добавления анимации к видео)
- создание онлайн досок (для систематизирования информации)
- создание интерактивных элементов и сайтов с помощью встроенного инструмента генерации кода
- совместная работа в реальном времени

Выбранный сценарий:
Открытие шаблона и изучение редактора

В рамках сценария пользователь открывает редактор, открывает шаблон, пробует его поменять, тем самым изучая возможности системы

### 2.1 Основные страницы и разделы

В рамках лабораторной работы исследуется информационная система Canva - конструктор для создания дизайна.

в системе используются следующие основные страницы и разделы:

- главная страница Сanva

## 4. Анализ серверной части и API

### 4.1. Серверная часть

- Серверная часть Canva построена на микросервисной архитектуре. Большинство сервисов являются ресурсно-ориентированными и управляют операциями с различными ресурсами Canva, такими как пользователи, документы, папки и медиа. В рамках выбранного сценария «Открытие шаблона и изучение редактора» можно предположить выполнение следующих серверных операций:

- получение данных дизайна пользователя

- поиск и получение данных доступных шаблонов

- сохранение изменений дизайна

- проверка прав пользователя на доступ к шаблону

- обработка запросов на редактирование элементов

Медиасервис управляет операциями с медиаресурсами, хранит идентификатор медиа, владельца, статус, метаданные и ссылку на расположение файла.

### 4.2. Передаваемые данные

При работе редактора между браузером и сервером передаются различные данные.

В зависимости от выполняемого действия это могут быть:

- идентификатор дизайна

- идентификатор шаблона

- параметры выбранного элемента

- данные пользователя и его сессии

- данные для сохранения изменений

| Статус	 | 200 OK                   |
| Назначение | Получение данных шаблона |
| Данные	 | Идентификатор шаблона    |

### 4.5. Хранилища данных

Canva использует несколько типов хранилищ данных. Исторически большинство ресурсно-ориентированных микросервисов представляли собой тонкий слой над MySQL на AWS RDS. По мере приближения количества медиафайлов к 1 миллиарду и их экспоненциального роста Canva перенесла метаданные медиаконтента в DynamoDB.

| Хранилище            | Предполагаемое назначение                               |
|----------------------|---------------------------------------------------------|
| DynamoDB             | Хранение метаданных медиа                               |
| База данных          | Хранение пользователей, проектов, страниц и настроек    |
| Файловое хранилище   | Хранение изображений, видео и других загруженных файлов |
| Кэш	               | Быстрый доступ к часто используемым данным              |
| Браузерное хранилище | Хранение части данных на стороне пользователя           |

## 5. Описание пользовательского сценария

### 5.1. Выбранный сценарий

Название сценария: открытие шаблона и изучение редактора.

Цель сценария: открыть шаблон, изменить его элементы, чтобы изучить возможности Canva.

### 5.2. Последовательность выполнения сценария

#### Этап 1. Пользователь открывает шаблон

Пользователь авторизуется в Canva, выполняет поиск и выбирает шаблон на главной странице или через вкладку «Шаблоны» в редакторе.

На этом этапе браузер загружает необходимые HTML-, CSS- и JavaScript-ресурсы.

#### Этап 2. Пользователь открывает шаблон в редакторе

Пользователь нажимает «Настроить этот шаблон», и шаблон открывается в редакторе.

#### Этап 3. Пользователь изучает структуру редактора

Редактор содержит плавающую панель редактирования, которая появляется при клике на элемент в верхней части области дизайна. Боковая панель предоставляет доступ к шаблонам, элементам, тексту, бренду и другим функциям.

#### Этап 4. Пользователь изменяет элементы шаблона

Пользователь выбирает элемент дизайна. Плавающая панель редактирования адаптивно отображает опции в зависимости от типа элемента: для текста — шрифт, размер, эффекты; для графики — цвет, обрезка; для изображений — рамка, фильтры, инструменты Magic Studio.

#### Этап 5. Клиентская часть взаимодействует с сервером

При изменении элементов изменения автоматически сохраняются. Клиентская часть может отправлять запросы на сервер для сохранения изменений.

#### Этап 6. Сервер обрабатывает запрос

Сервер принимает запрос и выполняет необходимые операции.

Сервер проверяет права пользователя на доступ к шаблону и обрабатывает данные дизайна.

#### Этап 7. Интерфейс отображает результат

JavaScript обрабатывает полученный результат и обновляет интерфейс.

Изменения отображаются в рабочей области редактора. Пользователь видит результат своего действия.

#### Этап 8. Пользователь меняет шаблон (опционально)

Пользователь может сменить шаблон через вкладку «Шаблоны» на боковой панели.

Для уже отредактированного дизайна система предложит выбор: заменить текущую страницу (отменив изменения) или добавить как новую страницу.

## 6. Построение архитектурной схемы

### 6.1. Архитектурная схема

Для демонстрационного варианта была построена упрощенная архитектурная схема информационной системы Canva.

На схеме представлены основные компоненты:

- пользователь

- браузер

- пользовательский интерфейс

- клиентская часть

- API

- серверная часть (микросервисы)

- хранилище данных

- внешние сервисы

Схема показывает направление взаимодействия между компонентами при выполнении сценария открытия шаблона и изучения редактора.

### 6.2. Взаимодействие компонентов

Основные взаимодействия в системе:

1. Пользователь выполняет действия в интерфейсе Canva

2. Браузер отображает интерфейс и выполняет клиентский код

3. Клиентская часть обрабатывает действия пользователя

4. При необходимости клиентская часть отправляет запрос через API

5. Сервер (микросервисы) обрабатывает полученный запрос

6. Сервер обращается к хранилищу данных

7. Сервер возвращает результат клиентской части

8. Клиентская часть обновляет интерфейс

9. Пользователь видит результат выполненного действия

Дополнительно серверная часть может взаимодействовать с внешними сервисами, необходимыми для работы отдельных функций системы.
